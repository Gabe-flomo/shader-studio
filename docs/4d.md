# 4D (first taste)

A small first step into a fourth dimension, built on the existing 3D ray marcher. Nothing in the march loop,
camera or lighting changed: the 4D part lives entirely inside a normal **Scene Group**.

## Slicing

A 4D shape is a distance function of a point with four coordinates, `p4 = (x, y, z, w)`. The screen shows 3D,
so we show a **slice**: the ray marcher asks the Scene Group for the distance at 3D points, **Lift to 4D**
gives each point the same fourth coordinate `w`, and the 4D shape measures that. Changing `w` moves the
slice through the shape (a hypersphere's slice is a ball of radius `sqrt(r² - w²)`: it swells, shrinks and
vanishes at `w = r`). Turning the shape in a plane that includes `w` changes which part of it the slice cuts,
so the 3D picture morphs although nothing in 3D moves.

Points travel as `vec4` (the graph already had the type), so no new socket type was needed.

## Slice direction

The slice is a flat 3D layer (a hyperplane) inside 4D, and Lift to 4D lets you choose which way it faces. A
direction is a unit normal `n`; the slice is every 4D point with `n · x = w`. The 3D point being measured
is carried onto it with an orthonormal basis: three 4D vectors `b0, b1, b2`, perpendicular to `n` and to each
other, so `p4 = b0·x + b1·y + b2·z + n·w`. (The shader gets the basis as the first columns of the Householder
reflection that carries the w axis onto `n`: `H q = q - 2 v (v·q) / (v·v)`, `v = e_w - n`, which needs no matrices.
Lengths are kept: `|p4|² = |pos|² + w²`.)

| Slice direction | normal `n` | what the slice meets first | tesseract (half size `h`) |
| --- | --- | --- | --- |
| Face-first | `(0, 0, 0, 1)` | a whole cubic cell | a cube, until `\|w\| = h`, then nothing |
| Edge-first | `(0, 0, 1, 1) / √2` | an edge | a box, longer than a cube, shortening to nothing at `\|w\| = h√2` |
| Corner-first | `(1, 1, 1, 1) / 2` | a corner | a point, tetrahedron, truncated tetrahedron, octahedron, and back; ends at `\|w\| = 2h` |
| Custom | two angles | | any; Tilt 60 / Swing 54.74 is corner-first, Tilt 45 / Swing 0 is edge-first (up to symmetry) |

Corner-first, as w sweeps from `2h` down through `-2h` (a tesseract's slice):

```
  w:   2h        1.5h       h          0.5h        0         -0.5h      -h         -2h
       •   ->   tetra  ->  tetra  ->  truncated ->  octa  ->  truncated -> tetra ->   •
       point     (grows)   (largest)   tetra      (6 verts)    tetra     (shrinks)  point
       1 vtx     4 vtx      4 vtx     12 vtx      6 vtx       12 vtx      4 vtx     1 vtx
```

Custom takes **Tilt** (how far `n` leans away from the w axis, 0 = face-first) and **Swing** (which way it leans
among x, y, z: `n = (sin a · cos b, sin a · sin b / √2, sin a · sin b / √2, cos a)`). Face-first compiles to
exactly the old `vec4(pos, w)`. Tests (`fourDSlices.test.ts`) check the basis is orthonormal, that the real shader's lift equals
`basis · pos + n · w`, that the slice's vertices (counted from the tesseract's edges) go 1, 4, 4, 12, 6, 12, 4, 1, and that the shader
agrees on the surface.

## Nodes (category "4D")

| Node | What it does |
| --- | --- |
| Lift to 4D | `p4 = basis · Scene Pos + n · w` for the chosen slice direction (face-first: `(Scene Pos, w)`); `w` is a live setting or a socket |
| Rotate 4D | turns `p4` in one of six planes by an angle in degrees, plus an optional Spin (deg/s, uses time) |
| Translate 4D | `p4 - (x, y, z, w)` |
| Hypersphere SDF | `length(p4) - r` |
| Tesseract SDF | the 4D box, half size plus optional rounding |

Like Rotate 3D, Rotate 4D moves the point the opposite way, so the shape turns from the first axis of the plane toward the second.

## The six rotation planes

In 4D you turn in a plane, not around an axis: two coordinates mix, the other two stay put. There are six:
`xy`, `xz`, `yz` (ordinary 3D turns; the shape just spins) and `xw`, `yw`, `zw` (a direction swaps with `w`;
the slice changes form). A tesseract turned in `xw` alone stretches along x and back; add a second plane (`yw`, `zw`)
and the slice becomes a many-faced solid. Turns compose and the order matters.

## Examples ("4D" folder)

- **Tesseract slice**: cut corner-first, w swept by an LFO (Play: Sweep, Centre, and the tesseract's half size inside the group): tetrahedron to octahedron and back, with shadows and occlusion on a floor.
- **Hypersphere in a tesseract**: a ball inside a hollow tesseract tray; an LFO sweeps `w` so the ball swells and shrinks. Play turns the box (Rotate 4D's Angle) and moves the cut (the plane's Height) directly inside the Scene Group. Shadows and occlusion on.
- **Tesseract, all three slices**: three tesseracts side by side, face-, edge- and corner-first, all reading the same w through ports.

## Shadows and occlusion with Scene Group ports

A Scene Group is a GLSL function `mapScene_x(vec3 p, extra...)`; its ports and wired settings become the extra
arguments. The March Loop always passed them, but Soft Shadow, SDF Ambient Occlusion, Fake SSS and the other
nodes that call the scene themselves wrote `mapScene_x(pos)`, so a scene whose settings came in through ports (a 4D
slice position from an LFO, say) could not have shadows. The assembler now rewrites every call a node
makes (`addSceneArgs`, in `compileStandardNode`) to pass the same arguments, so shadows, occlusion and the march
see the same shape. Scenes without ports produce byte-identical shaders (existing golden snapshots are unchanged;
only the 4D examples changed).

## Play inside Scene Groups

Play controls can target a setting one level inside a Scene Group, like a plain group: the target is
`sceneGroupId::innerNodeId::param`, bound to the same live uniform (`innerNodeId::param`). They appear in the Play
control list, in the slider right-click "Add to Play controls" (also from inside the group), and in Suggest controls (which
looks into Scene Groups whatever the Randomize "Inside groups" option says). A setting a wired port or a socket has
taken over is not offered (it is replaced in the shader). Publishing a group as a node still does not surface Scene Group settings.
