# 4D (first taste)

A small first step into a fourth dimension, built on the existing 3D ray marcher. Nothing in the march loop,
camera or lighting changed: the 4D part lives entirely inside a normal **Scene Group**.

## Slicing

A 4D shape is a distance function of a point with four coordinates, `p4 = (x, y, z, w)`. The screen shows 3D,
so we show a **slice**: the ray marcher asks the Scene Group for the distance at 3D points, **Lift to 4D**
gives each point the same fourth coordinate `w`, and the 4D shape measures that. Changing `w` moves the
slice through the shape (a hypersphere's slice is a ball of radius `sqrt(r² - w²)`: it swells, shrinks and
vanishes at `w = r`). Turning the shape in a plane that includes `w` changes which part of it the slice cuts,
so the 3D picture morphs although nothing in 3D moves.

Points travel as `vec4` (the graph already had the type), so no new socket type was needed.

## Slice direction

The slice is a flat 3D layer (a hyperplane) inside 4D, and Lift to 4D lets you choose which way it faces. A
direction is a unit normal `n`; the slice is every 4D point with `n · x = w`. The 3D point being measured
is carried onto it with an orthonormal basis: three 4D vectors `b0, b1, b2`, perpendicular to `n` and to each
other, so `p4 = b0·x + b1·y + b2·z + n·w`. (The shader gets the basis as the first columns of the Householder
reflection that carries the w axis onto `n`: `H q = q - 2 v (v·q) / (v·v)`, `v = e_w - n`, which needs no matrices.
Lengths are kept: `|p4|² = |pos|² + w²`.)

| Slice direction | normal `n` | what the slice meets first | tesseract (half size `h`) |
| --- | --- | --- | --- |
| Face-first | `(0, 0, 0, 1)` | a whole cubic cell | a cube, until `\|w\| = h`, then nothing |
| Edge-first | `(0, 0, 1, 1) / √2` | an edge | a box, longer than a cube, shortening to nothing at `\|w\| = h√2` |
| Corner-first | `(1, 1, 1, 1) / 2` | a corner | a point, tetrahedron, truncated tetrahedron, octahedron, and back; ends at `\|w\| = 2h` |
| Custom | two angles | | any; Tilt 60 / Swing 54.74 is corner-first, Tilt 45 / Swing 0 is edge-first (up to symmetry) |

Corner-first, as w sweeps from `2h` down through `-2h` (a tesseract's slice):

```
  w:   2h        1.5h       h          0.5h        0         -0.5h      -h         -2h
       •   ->   tetra  ->  tetra  ->  truncated ->  octa  ->  truncated -> tetra ->   •
       point     (grows)   (largest)   tetra      (6 verts)    tetra     (shrinks)  point
       1 vtx     4 vtx      4 vtx     12 vtx      6 vtx       12 vtx      4 vtx     1 vtx
```

Custom takes **Tilt** (how far `n` leans away from the w axis, 0 = face-first) and **Swing** (which way it leans
among x, y, z: `n = (sin a · cos b, sin a · sin b / √2, sin a · sin b / √2, cos a)`). Face-first compiles to
exactly the old `vec4(pos, w)`. Tests (`fourDSlices.test.ts`) check the basis is orthonormal, that the real shader's lift equals
`basis · pos + n · w`, that the slice's vertices (counted from the tesseract's edges) go 1, 4, 4, 12, 6, 12, 4, 1, and that the shader
agrees on the surface.

## Nodes (category "4D")

| Node | What it does |
| --- | --- |
| Lift to 4D | `p4 = basis · Scene Pos + n · w` for the chosen slice direction (face-first: `(Scene Pos, w)`); `w` is a live setting or a socket |
| Rotate 4D | turns `p4` in one of six planes by an angle in degrees, plus an optional Spin (deg/s, uses time) |
| Translate 4D | `p4 - (x, y, z, w)` |
| Hypersphere SDF | `length(p4) - r` |
| Tesseract SDF | the 4D box, half size plus optional rounding |
| Phase 2 nodes | see below: more shapes, Scale / Repeat / Fold / Twist, Noise 4D |

Like Rotate 3D, Rotate 4D moves the point the opposite way, so the shape turns from the first axis of the plane toward the second.

## The six rotation planes

In 4D you turn in a plane, not around an axis: two coordinates mix, the other two stay put. There are six:
`xy`, `xz`, `yz` (ordinary 3D turns; the shape just spins) and `xw`, `yw`, `zw` (a direction swaps with `w`;
the slice changes form). A tesseract turned in `xw` alone stretches along x and back; add a second plane (`yw`, `zw`)
and the slice becomes a many-faced solid. Turns compose and the order matters.

## Examples ("4D" folder)

- **Tesseract slice**: cut corner-first, w swept by an LFO (Play: Sweep, Centre, and the tesseract's half size inside the group): tetrahedron to octahedron and back, with shadows and occlusion on a floor.
- **Hypersphere in a tesseract**: a ball inside a hollow tesseract tray; an LFO sweeps `w` so the ball swells and shrinks. Play turns the box (Rotate 4D's Angle) and moves the cut (the plane's Height) directly inside the Scene Group. Shadows and occlusion on.
- **Tesseract, all three slices**: three tesseracts side by side, face-, edge- and corner-first, all reading the same w through ports.

## Shadows and occlusion with Scene Group ports

A Scene Group is a GLSL function `mapScene_x(vec3 p, extra...)`; its ports and wired settings become the extra
arguments. The March Loop always passed them, but Soft Shadow, SDF Ambient Occlusion, Fake SSS and the other
nodes that call the scene themselves wrote `mapScene_x(pos)`, so a scene whose settings came in through ports (a 4D
slice position from an LFO, say) could not have shadows. The assembler now rewrites every call a node
makes (`addSceneArgs`, in `compileStandardNode`) to pass the same arguments, so shadows, occlusion and the march
see the same shape. Scenes without ports produce byte-identical shaders (existing golden snapshots are unchanged;
only the 4D examples changed).

## Play inside Scene Groups

Play controls can target a setting one level inside a Scene Group, like a plain group: the target is
`sceneGroupId::innerNodeId::param`, bound to the same live uniform (`innerNodeId::param`). They appear in the Play
control list, in the slider right-click "Add to Play controls" (also from inside the group), and in Suggest controls (which
looks into Scene Groups whatever the Randomize "Inside groups" option says). A setting a wired port or a socket has
taken over is not offered (it is replaced in the shader). Publishing a group as a node still does not surface Scene Group settings.

## Phase 2: shapes, transforms and noise

All of these take a `vec4` point and give a `float` distance (shapes) or a `vec4` (transforms), so the existing float combine nodes (Union,
Subtract, Intersect, Smooth) work on them and "Fits here" offers them after any 4D shape (the 4D examples wire every shape into a Union).

### Shapes: exact or bound

An **exact** distance is the true distance to the shape. A **bound** is exact inside and never *over*-estimates outside (and is 1-Lipschitz), so
marching by it is safe but takes a few more steps near corners. Tests check both: the bounds against thousands of sampled surface points.

| Node | Formula | Distance | Slice at w (face-first, no turn) |
| --- | --- | --- | --- |
| Hypersphere | `length(p) - r` | exact | ball of radius `sqrt(r² - w²)` |
| Tesseract | 4D box | exact | cube until `\|w\| = h` |
| Duocylinder | disc(xy, r1) × disc(zw, r2) | exact | cylinder along z, half height `sqrt(r2² - w²)` |
| Spherinder | ball(xyz, r) × segment(w, h) | exact | ball while `\|w\| < h` |
| Cubinder | square(xy, h) × disc(zw, r) (the square × circle reading) | exact | box, shortening as w grows |
| Cylindrical Prism | disc(xy, r) × rectangle(zw) (a cylinder × segment) | exact | cylinder while w is inside |
| Ditorus ("tiger") | `length(vec2(length(p.xy) - R1, length(p.zw) - R2)) - r` | exact | torus, rings, two-lobed shapes |
| Clifford Torus | the same with `R1 = s cos a`, `R2 = s sin a` (a = Balance, 45° is the Clifford torus) | exact | linked rings / torus |
| 5-cell | max of the five face-plane distances | **bound** | tetrahedron-like |
| 16-cell | `(\|x\| + \|y\| + \|z\| + \|w\| - s) / 2` | **bound** | octahedron at w = 0 |
| 24-cell | `max(max \|c\|, sum \|c\| / 2) - R/√2` | **bound** | octahedron-like |

Products of convex sets (duocylinder, spherinder, cubinder, prism) are exact because the distance to `A × B` is `length(max(vec2(a, b), 0)) + min(max(a, b), 0)`
from the two signed distances. The polytopes take **Radius = distance to a corner** (the faces are at R/4, R/2 and R/√2). The sphere-cone family
was left out (not cheap to make exact). The 5-cell has a corner along +w.

### Transforms

- **Scale 4D**: `p / s` in, `dist * s` out (wire the shape's distance back through it); Scale 2 is twice as big (the opposite of Scale 3D).
- **Repeat 4D**: per-axis cell size, a switch per axis, and an optional Count limit (0 = forever). Put it before the Rotate 4D to turn each copy, after to turn the lattice.
- **Mirror / Fold 4D**: `abs` on the chosen axes, plus one fold across a slanted hyperplane (`x = y`, ..., `x + y + z + w = 0`): a reflection `p - 2 min(p·n, 0) n`. Folds keep lengths, so distances stay safe.
- **Twist 4D**: rotates in a chosen plane by `amount × coordinate along another axis`. Not Lipschitz: the true distance can be up to `1 + k·r` shorter than measured. The node's **Step scale** multiplies the distance back (use `1 / (1 + k·r)`), or lower the March Loop's Step Scale.

### Noise 4D

Smooth value noise (quintic interpolation of hashed lattice corners, 1 to 4 octaves) at a `vec4`: **Value** 0 to 1 and **Signed** −1 to 1.
Deterministic (a fract-based hash, no sine). Put time in `w` (Lift to 4D, w from Time) to evolve a 3D pattern smoothly, or add Signed (times a small amount) to a 4D shape's distance to roughen it.

### Examples (phase 2)

- **Duocylinder dance**: a duocylinder turning in xw and yz at once.
- **The 24-cell**: corner-first slice sweep (for a 24-cell this direction is the normal of one of its own octahedral cells, so the slice begins as an octahedron and becomes a truncated octahedron).
- **Clifford torus**: turning slowly in xw and yw, roughened by Noise 4D; the slice shows linked rings.
- **Lattice of hyperspheres**: Repeat 4D of hyperspheres, turning in xw: the equal balls of the slice swell and shrink in waves.
- **Shape gallery**: all ten shapes in two rows, turning together.

## Phase 3: projection

**Slicing shows one cross-section; projection shows the whole object.** A slice is what is *at* one w. A projection squashes every w into 3D, like the shadow of a hand or a cube drawn on paper: nothing is cut away, but depth along the fourth axis is lost or hinted at (by size, in perspective). Both are ordinary 3D distance functions in a Scene Group, so lighting, shadows, glow and the march loop need no changes. Nodes are in the "4D" category, group "Project".

| Mode | Node | What you see | Distance |
| --- | --- | --- | --- |
| Wireframe | **4D Wireframe** | a polytope's edges and corners as tubes and balls | exact for the tubes and balls (min of segment / point distances) |
| Solid shadow | **Project 4D** | the whole shape squashed along w | **approximate** (min over w samples) |
| Stereographic | **Stereographic 4D** + **Stereographic Distance** | all of 3D laid onto the 3-sphere, for shapes that live there | a safe lower bound, from the conformal factor |

### 4D Wireframe

Choose a polytope; corners and edges are generated in TypeScript (`polytope()` in `fourDProject.ts`) and the node emits **unrolled GLSL** for that polytope only (one segment test per edge, one projected corner per vertex; no arrays, so it runs in the CPU test helper too).

| Polytope | Corners | Edges | Corner coordinates (before scaling to the radius) |
| --- | --- | --- | --- |
| Tesseract | 16 | 32 | (±1, ±1, ±1, ±1) / 2; an edge joins corners that differ in one sign |
| 5-cell | 5 | 10 | (±1, ±1, ±1 with the parity rule, −1/√5) normalised, and (0, 0, 0, 1); every pair is an edge |
| 16-cell | 8 | 24 | ±e_k; every pair except opposite corners |
| 24-cell | 24 | 96 | (±1, ±1, 0, 0) / √2 in every arrangement; an edge joins corners with dot = 1/2 |

The corners are turned by **two 4D turns** (each a plane, an angle and a spin in degrees a second; the same mixing as Rotate 4D but turning the *shape*: from the first axis toward the second; turn 1 is applied first), then projected:

- **Perspective**: a camera on the w axis at *Camera distance* `d`: `p.xyz * d / (d - p.w)`. (The spec's `p.xyz / (d - p.w)` times `d`, so a corner at w = 0 keeps its size.) Corners at larger w are closer and bigger, at smaller w far and small: a tesseract is a cube inside a cube, corners joined by eight struts. Perspective keeps straight lines straight, so each edge is exactly a straight 3D segment. `d` must be above the radius (the nearest corner is clamped at `d - w >= 0.05`).
- **Orthographic**: `p.xyz`, w is dropped.

The distance is `min(sqrt(min segment²) - edge radius, sqrt(min corner²) - corner radius)`: exact. **Speed**: at most 96 segment tests and 24 corners (24-cell). A **bounding-sphere early-out** returns `length(p) - reach - thickness` (a true lower bound) when the point is more than 0.25 beyond the shape's reach (`R · d/(d − R)` in perspective, `R` in orthographic), and does no edge work. Edge and corner sizes are constant in 3D (they do not shrink with perspective).

### Project 4D: the volumetric shadow (an approximation)

Pick a built-in 4D shape (duocylinder, tesseract, hypersphere, spherinder, cubinder, ditorus, Clifford torus, 5/16/24-cell), its size and the same two turns. The node measures the shape's 4D distance at `Samples` values of `w` between `−W range` and `+W range` (the point is turned first) and takes the **smooth minimum** (the *Smooth* setting is a multiple of the spacing between samples; 0 is a hard minimum), then multiplies a positive result by **Step scale**.

Why it works and how it fails. For a 4D point `(p, w)` the distance to the shape is `d4(p, w)`, and the distance from `p` to the shadow in 3D is `min over w of d4(p, w)` *exactly* (the nearest shape point `q` gives `|p − πq| ≤ sqrt(|p − πq|² + (w − q_w)²)`, with equality at `w = q_w`). So with infinitely many samples the minimum is the true distance to the shadow. With `N` samples spaced `h` apart:

- the result is never *less* than the true distance (it is a distance to the slices at the sampled w), so it is **not a lower bound**: a march can overshoot the true surface, by at most about `sqrt(d² + (h/2)²) − d`, which is largest right at the surface (about `h/2`);
- the shadow is the union of `N` thin slices, so a coarse count shows **steps** between layers and the silhouette sits a little inside the true one; *Smooth* blends the steps (and inflates by up to `smooth · h / 4`);
- the *Step scale* hint (default 0.8) shortens positive distances to absorb the overshoot; lower it (0.5) with few samples;
- the range must cover the shape's reach along w, or the shadow is cut short (a shape turned in xw reaches as far as its largest radius).

Cost: one shape evaluation per sample (default 20). Up to 48 samples. Tests check the exact case (an odd count includes w = 0, and a duocylinder's shadow is a cylinder), the "never less, and by no more than the half-spacing step" bound, and Step scale / Smooth.

### Stereographic 4D, Stereographic Distance and Hopf Circles

The inverse stereographic map `R³ → S³` (pole at +w, so the origin goes to the south pole and infinity to the north pole): with `x = pos / Scale`, `X = (2x, |x|² − 1) / (|x|² + 1)`, and the 4D point is `Radius · X`, then turned by the two 4D turns. A 4D shape that lives on (or near) the 3-sphere (Clifford Torus, Hopf Circles) is then seen as it is mapped back into 3D: a Clifford torus is an ordinary torus of revolution, and the Hopf circles are rings that fill space (circles stay circles; those through the pole are lines).

The map is **conformal** and stretches lengths by `λ = 2 Radius / (Scale · (1 + |x|²))` per unit of `pos`. A distance measured in 4D is therefore `≈ λ ×` the 3D one, so the node outputs a **Factor** `1/λ = Scale (1 + |x|²) / (2 Radius)` and **Stereographic Distance** takes `E = d4 · Factor`. `E` alone is not safe far from the middle (λ falls as you leave it, so a long step goes through thin rings); λ can change by at most a factor `e` per `Scale` of travel (`|∇ ln λ| ≤ 1/Scale`), so the true 3D distance `d` satisfies `d · e^(d/Scale) ≥ E`, and `min(E, Scale) · e^(−min(E, Scale)/Scale)` is a safe lower bound: equal to `E` for small distances, **never over the true distance**, capped at `Scale / e` far away. Inside the shape `E` is used as it is. The correction is a separate node, because the 4D shape's point comes from Stereographic 4D (one node doing both would be a cycle). Tests check the round trip `3D → S³ → 3D`, that the GLSL matches the TypeScript map, that the corrected distance never exceeds a brute-force distance to a Clifford torus, and that it is about 1-Lipschitz at sampled points (the output's slope is the shape's slope times `g'(E)`, so it could exceed 1 a little in principle; the test allows 1.05 and measures about 0.83 at 200 sampled pairs).

**Hopf Circles SDF**: fibres of the Hopf fibration, each a great circle through `u = (cos(η/2), 0, sin(η/2) cos φ, sin(η/2) sin φ)` and `v = (0, cos(η/2), −sin(η/2) sin φ, sin(η/2) cos φ)`, with the exact distance to a tube around it, `sqrt((ρ − R)² + perp²) − thickness` (`ρ` = length in the plane of the circle). Any two circles link once; the circles of one latitude `η` lie on one torus (at 90° the Clifford torus: the Villarceau circles). Settings: fibres per ring (up to 24), latitude, rings (up to 3) and their spacing, *Phase* (the Hopf flow: slides every circle along itself).

### Limits

- **Projection hides depth.** In orthographic the w of a corner is gone; perspective only hints at it by size. Parts of the shape overlap in the picture.
- Wireframe sizes (tube and corner radius) are constant in 3D. Tubes go through each other where edges cross in projection; that is a property of projection, not a bug.
- The shadow is **approximate** (above). It is for the built-in shapes only: it needs the shape as a function, which a wired chain of 4D nodes is not (a group node that re-evaluates a subgraph at many w would be the general version).
- Stereographic: distances far from the origin are small (the cap is `Scale / e`), so scenes want a bounding sphere (the Hopf example intersects one); tube *thickness* in 3D grows with distance from the middle by the same factor λ.
- The polytope shapes in 4D (the *SDF* nodes) are still bounds, not exact distances; the wireframe is separate and exact.

## 4D straight to 2D

You don't need a 3D scene to see 4D. Two nodes work on the flat picture:

- **4D Wireframe 2D**: a polytope (tesseract, 5-cell, 16-cell, 24-cell) turned in 4D, then projected 4D → 3D along w and 3D → 2D along z. Its output is a 2D distance, like a circle's: wire UV in, then SDF Glow or SDF Fill. Example: **4D: Flat tesseract (4D → 2D)**.
- **Plane Slice 4D**: turns each UV point into the 4D point (x, y, z, w). Wire it through Rotate 4D into any 4D shape, and the shape's distance is the cross-section of the 4D object by a plane: flat shapes that split, merge and morph as the plane turns. Example: **4D: Plane through a duocylinder (4D → 2D)**.

Adding a 4D *shape* on its own still builds a 3D scene for it (smart placement). To use one in 2D, add Plane Slice 4D first and wire the shape from it.

## How to use projection, step by step

1. **Classic tesseract in 3D:** add **4D Wireframe** at the top level. Playfield builds the Scene Group, camera and march loop for you. Set Turn 1 to plane xw with a spin (around 20°/s) and Turn 2 to yz (around 12°/s).
2. **The same in 2D:** UV → **4D Wireframe 2D** → **SDF Glow** → Output. Lower Line width and raise the glow's Falloff for thin bright lines.
3. **A solid shadow:** inside a Scene Group, wire Scene Pos → **Project 4D**, pick a shape (duocylinder, tesseract, Clifford torus…). Use Smooth to hide the layers and Step scale 0.8 on the march loop.
4. **Linked rings:** Scene Pos → **Stereographic 4D** → **Hopf Circles SDF** → **Stereographic Distance** (wire its Factor and Scale from the Stereographic 4D node) → Scene Output. Adding Stereographic 4D at the top level builds this chain for you.

## 4D fractals

- **Quaternion Julia SDF**: every 4D point q is iterated q → q² + c (quaternion squaring); points that never escape are inside. The constant c (four numbers) picks the set, and moving it slowly makes the slice boil and curl. Iterations 8–12 is plenty.
- **Quaternion Mandelbrot SDF**: from q = 0, q → q² + p with p the 4D point.

Both use the fractal distance estimate (a safe lower bound): use a Step Scale of about 0.8 on the march loop. Both work in any 4D chain (Lift to 4D, Rotate 4D, then the fractal). Example: **4D: Quaternion Julia**, where two LFOs drift c through Scene Group ports.
