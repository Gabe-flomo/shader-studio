# Expression Builder: plan

A builder, like the 2D Scene Builder, 3D Scene Builder and Agent Rules, for growing an expression
step by step out of moves taken from real GLSL. You start from a seed (UV, a world position, time,
or whatever flows through a socket). Each step shows a grid of next moves as small live pictures of
*your* expression with that move applied. Pick one and keep going. The result is an Expression Block
or a Custom Function node, with **Edit in builder** to reopen the chain.

The aim is exploring: "what if I take UV and do this, then this to the result?" It covers swizzle
cross-coupling, folds, repeats, warps, and colouring by world space rather than per object, without
needing to know those tricks by name first.

Agreed with the user (2026-10-09):

- It is a builder in the Builders list, and it outputs an Expression Block or a Custom Function node.
- GLSL you import feeds the move corpus too. It stays on your machine; only the app's own examples ship.
- Moves are context-aware: 2D or 3D, and the graph they sit in.
- Later: a semantic representation of graphs, so searching moves (and graphs) can go by meaning.

## What it builds on

| Piece | Where | Used for |
|---|---|---|
| Code explorer corpus | `src/codeExplorer/` (extract, antiUnify, corpus, prebuilt index) | Every expression site in the examples, already generalised into shapes (`pow(# / abs(sin(_a * # + _b) / #), #)`), with provenance |
| Parser, types, roles | `src/lib/glslPatterns/` (parse, types, roles) | What a move takes and gives (vec2 → vec2, vec3 → float), and what it acts on (space, colour, distance, time) |
| Generalise | `glslPatterns/generalise.ts` | Literals → slider holes, free names → inputs ("Make a node from this") |
| CPU evaluation | `glslPatterns/evaluate.ts`, `worked.ts` | A candidate's value range over the picture, without the GPU |
| Idioms | `glslPatterns/idioms.ts` | Naming what you built ("a domain warp", "a kaleidoscope fold") |
| Build-up pictures | `components/explain/BuildUpView.tsx`, `buildUpHost.ts` | Small real renders of an expression in its graph, with a cost fallback |
| Pattern index | `src/patterns/` (catalogue, patternIndex, mine) | Techniques in a graph: the context a socket sits in |
| Builder shell | `components/builders/` (BuilderWindow, help, recipe chip) | The window, tabs, help cards, recipe text, Open as nodes |

## 1. Moves

A **move** is a typed template with holes, mined from real code:

```
x * k                                  zoom              vec2 → vec2 (space)
fract(x * k) - 0.5                     repeat            vec2 → vec2 (space)
abs(x) - c                             fold              vecN → vecN
x + a * sin(x.yx * k + t)              cross-warp        vec2 → vec2
vec2(atan(x.y, x.x), length(x))        polar             vec2 → vec2
length(x) - r                          circle            vecN → float (distance)
0.5 + 0.5 * cos(x * k + vec3(0,2,4))   colour by space   vec3 → vec3 (colour)
```

- **Mining.** Every assignment and sub-expression in the corpus that transforms a variable becomes a
  candidate. Its other names become holes (`_a`, `_b`) and its numbers become sliders (with the
  values they had as defaults and ranges). Duplicates collapse, using the Code explorer's
  generalised shapes.
- **What each move records:**
  - its signature (input and output types) and the role it acts on;
  - how often it is used;
  - **where it came from** (example names, or "your import: Shadertoy tunnel");
  - the contexts it was used in (below).
- **Generated moves.** Some families are too rare in any one shader but are exactly the interesting
  space, so they are generated by type rather than mined:
  - swizzles (`x.yx`, `x.zxy`);
  - one component driving another (`x.x += f(x.y)`);
  - products across dimensions;
  - rotations in each plane.
- **Sources.** The shipped examples (prebuilt, like the Code explorer index) plus everything the user
  imports or writes (indexed locally, as the Code explorer already does).

## 2. Context

The same `sin` means different things in 2D and in a 3D scene, so every move is tagged with the
contexts it was used in:

- **Dimension:**
  - 2D picture space (UV);
  - 3D world space (inside a Scene Group or March Loop);
  - 3D on a surface (hit position, normal);
  - time only (1D).
- **Role in the graph:** what fed the variable (a UV node, a March Loop's position, a Normal, Time) and
  what the result went into (a distance, a colour, a mask, a palette).
- **Techniques around it:** from the pattern index (domain warping, kaleidoscope, raymarching, glow…).

A seed from a socket carries the same tags, so moves rank higher when they were used in a context
like yours: a 3D world-space seed feeding a colour gets "colour by space" moves first.

## 3. The builder

- **Seeds:**
  - from the Builders list (pick UV, World position, Time, or a 1D / 2D / 3D variable);
  - from a socket or wire (right-click → **Build an expression from here**), seeded with what flows
    there and knowing its context.
- **The chain.** The expression so far, one line per step (the build-up view's rows). Click a step to
  go back to it.
- **The grid of next moves.** Each tile shows a small live render of your expression with that move
  applied (the build-up host, so it sees the real graph, wiring and all). Hover a tile to show it
  big. Pick it to make it the next step.
- **Holes are sliders.** Tune k or a on the tile before you pick it, and still afterwards.
- **Branches.** Pin candidates side by side. Going back and picking something else keeps the old path
  as a branch (a history tree, not a single undo line).
- **Nesting.** A move's hole can be another built expression (the argument of a `sin`, say), built in
  a nested chain.
- **Iterate.** Apply a move N times, each pass varied, optionally adding up. Folds become fractals and
  warps become fluid.
- **Views:**
  - 1D as a plot (TransferPlotView);
  - 2D as a picture;
  - 3D on a slice plane you can move, or live on your scene's world position when seeded from a
    3D socket.
- **Output:** an Expression Block (one line per step, each with a note on what it does and where the
  move came from), or a Custom Function node with the holes as inputs. The recipe text round-trips:
  Edit in builder reopens the chain.

## 4. Smart ranking (no AI)

1. **What usually comes next.** Order statistics over the corpus (which move follows which in the
   same variable's chain), for the seed's context. `fract → - 0.5 → length` (cells, then circles)
   ranks after a repeat.
2. **Dull results drop.** Each candidate runs on the CPU over the picture (evaluate.ts). It sinks or
   hides when it is:
   - constant;
   - NaN or infinite;
   - too fine to see (aliasing: high frequency relative to a pixel);
   - the same as the current expression.

   The rest rank by how much they change the picture.
3. **Naming.** Idiom recognition names what the chain has become ("you just built a domain warp"),
   and that unlocks its usual finishing moves (cell id → random colour per cell).
4. **Provenance.** Every move links to the shaders that use it ("used in: Fractal Rings, Spiral
   Tunnel…"), via Find uses.
5. **Surprise me.** A random chain drawn from the order statistics, for the current seed.
6. **The local model** only explains the finished expression (docs/explain-model.md).

## 5. Semantic graphs (later)

A representation of whole graphs for searching by meaning (moves, examples, the user's graphs):

- **What it combines:**
  - the techniques found in the graph (the pattern index);
  - its node types, weighted by how rare they are;
  - its moves;
  - an image embedding of its picture (MobileCLIP, which the user wants put to real use).
- **What it's for:**
  - "graphs like this one";
  - "moves used in graphs like mine";
  - free-text search ("tunnel with rings").

It's planned with the Suggestion hub and the Query explorer, not built in the first phases.

## Phases

| Phase | What | Done when |
|---|---|---|
| 1 | Move catalogue: mine the examples (prebuilt) and the user's imports (local) into typed, counted, context-tagged moves with provenance; generated swizzle moves | A test lists ≥ 150 distinct moves across 2D, 3D and 1D, each with a signature, contexts and sources |
| 2 | The builder window: seeds, the chain, the grid of next moves as live pictures, sliders, output as an Expression Block | A UV seed → 3 moves → an Expression Block that compiles and matches the preview |
| 3 | Ranking: order statistics by context, the dull-move filter, idiom naming, provenance links, Surprise me | Candidate lists for 2D and 3D seeds put context-appropriate moves first (tested against held-out examples) |
| 4 | Branches, nesting, Iterate; the socket seed (right-click → Build from here) with its context; 3D slice and live world-space views | Colour by world space built from a March Loop position in a few clicks |
| 5 | Custom Function output, recipe round trip (Edit in builder), the Do bar ("new expression") | Reopening a built block restores its chain |
| Later | Semantic graphs (section 5) | |

Each phase is one PR with tests. Moves and ranking are pure modules (`src/exprBuilder/`), and the
window lives with the other builders (`components/builders/`).
